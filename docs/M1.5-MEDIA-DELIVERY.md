# M1.5 — Media delivery contracts and local HTTP host

## Scope

M1.5 adds the first real media-byte transport to the development toolchain. UCP control remains on WebSocket; media bytes are served over HTTP(S). This milestone provides a sender-side, single-file HTTP host and expands `media.load` descriptors for local/remote delivery, HLS/DASH/progressive source declarations, metadata, and external audio/subtitle tracks.

This is not yet a production media engine. The receiver simulator does not fetch, demux, decode, render, or switch tracks. HLS manifests are described, not packaged or recursively served by the local host.

## Local sender-hosted media

`tools/media-host` serves explicitly granted files from configured roots. A grant has:

- one canonical file path inside an approved root;
- a cryptographically random 256-bit bearer token;
- one opaque file ID;
- an expiry timestamp and explicit revocation function;
- a detected MIME type and file size.

The URL is scoped to one file. There is no directory listing or arbitrary path parameter. File real paths are checked against approved roots, including symlink resolution. The token is stored as a SHA-256 digest. Expired/revoked/unknown grants return 404.

### HTTP behaviour

| Request | Behaviour |
|---|---|
| `GET` | `200` full file, or `206` for one valid byte range |
| `HEAD` | Headers and content length without body |
| `Range: bytes=start-end` | Single inclusive byte range |
| `Range: bytes=start-` | From start to end of file |
| `Range: bytes=-suffix` | Last suffix bytes |
| Invalid/multiple/unsatisfiable range | `416` with `Content-Range: bytes */size` |
| Other methods | `405`, `Allow: GET, HEAD` |

Responses include `Accept-Ranges: bytes`, `Content-Length`, MIME type, `Cache-Control: no-store`, and `X-Content-Type-Options: nosniff`.

## Start on Windows

From the repository root:

```powershell
pnpm install
pnpm --filter @universalcast/media-host dev -- --root "D:\Media" --file "D:\Media\sample.mp4" --host 0.0.0.0 --port 8766 --ttl-minutes 15
```

Use the printed LAN URL in the `media.load` request. The receiver must be able to reach the sender's LAN IP and TCP port. If necessary, allow TCP 8766 through Windows Firewall for Private networks only. Do not send `localhost` or `127.0.0.1` to a different device.

Example descriptor:

```json
{
  "mediaId": "episode-001",
  "title": "Episode 1",
  "sources": [
    {
      "uri": "http://192.168.2.15:8766/media/<token>/<file-id>",
      "mimeType": "video/mp4",
      "protocol": "progressive",
      "delivery": "local",
      "expiresAt": "2026-11-09T23:59:00.000Z"
    }
  ],
  "metadata": { "durationMs": 1440000, "width": 1920, "height": 1080, "bitrate": 5000000 },
  "tracks": [
    { "id": "audio-en", "kind": "audio", "language": "en", "label": "English", "isDefault": true },
    { "id": "sub-en", "kind": "subtitle", "language": "en", "label": "English", "mimeType": "text/vtt", "uri": "https://example.invalid/subtitles/en.vtt" }
  ]
}
```

The token is a bearer secret. Anyone who obtains it can read the granted file until expiry or revocation. Plain HTTP exposes the token and media to LAN observers. Use only trusted LANs for this development milestone. Production must use paired-device authorization and a protected transport (TLS or equivalent), enforce grant ownership, and avoid placing bearer secrets in logs/analytics.

## Remote URL SSRF policy

`assertPublicRemoteUrl()` checks HTTP(S), rejects embedded credentials and local hostnames, resolves all A/AAAA records, and rejects a host if any resolved address is non-public. Local sender-hosted media is a separate delivery mode and is allowed to use private LAN addresses.

This helper is a policy primitive, not a complete secure fetcher. A production receiver must validate immediately before connecting, pin or verify the actual connected address to prevent DNS rebinding, revalidate every redirect, cap redirects/timeouts/response sizes, and avoid forwarding credentials across origins. HLS playlists, variants, segments, encryption keys, subtitles and redirects each need the same policy.

## Tests

```powershell
pnpm --filter @universalcast/media-host test
pnpm --filter @universalcast/media-host typecheck
pnpm --filter @universalcast/receiver-simulator test
pnpm --filter @universalcast/receiver-simulator typecheck
```

The media-host tests cover full-file GET, MIME, byte ranges, suffix/open-ended ranges, HEAD, invalid/multiple ranges, missing/revoked grants, root confinement, TTL bounds and remote URL policy. Receiver tests cover local expiry descriptors and audio/subtitle metadata validation.

## Explicitly deferred

- Android/TV media decoding and actual playback.
- HLS playlist rewriting/segment proxying and DRM.
- Multi-range requests and upload support.
- Production TLS, pairing, grant persistence, quotas and rate limiting.
- A fully hardened DNS-pinned remote fetcher.
