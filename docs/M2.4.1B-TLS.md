# M2.4.1b - Android TLS WebSocket transport

Status: implementation added; device interoperability validation pending.

## Scope

The Android receiver now derives a TLS 1.2 server context from the existing P-256 Android Keystore identity. Java-WebSocket serves the existing UCP dispatcher over WSS on port 8766. The existing development `ws://` endpoint remains on port 8765 for the M2.2/M2.3 simulator workflow.

Both endpoints and DNS-SD discovery are restricted to debug builds. Release builds expose no remote-control listener or receiver discovery until pairing, sender authentication, and role authorization are implemented. The debug WSS endpoint is still unauthenticated: TLS encrypts traffic and identifies the receiver certificate, but it does not establish sender identity or authorize commands. Use only on a controlled development LAN.

## Identity and transport behavior

- The Android Keystore private key is passed to the platform `KeyManagerFactory`; key bytes are never exported.
- The server is pinned to TLS 1.2 for Android API 23 compatibility.
- Before starting WSS, the app checks certificate validity, EC key type, self-signature, and digital-signature usage when the certificate declares key usage.
- The app logs only the public certificate SHA-256 fingerprint for manual development pinning.
- DNS-SD continues to advertise the existing plaintext development endpoint (`tls=0`). It does not claim WSS availability or publish a fingerprint until sender discovery and pairing are updated.
- TLS setup failure leaves the debug plaintext development endpoint available and reports WSS as unavailable. This fallback is debug-only and must not be carried into production.

## Validation

Build the debug APK with `apps/android-receiver/gradlew.bat :app:assembleDebug`. Then on an Android TV or emulator, inspect the `UniversalCastIdentity` log for the fingerprint and confirm that a WSS client pinned to that fingerprint can complete the TLS handshake on port 8766. A client with a different fingerprint must reject the connection before sending UCP data. The app has no WSS sender-side pinning test yet, so M2.4.1b is not complete until cross-platform device verification passes.

Do not treat a successful APK build as proof that Android Keystore's generated certificate works for TLS on every supported Android TV device.

## Next

M2.4.1c must add a Node client that validates the exact certificate fingerprint and exercises the existing UCP handshake over `wss://`. M2.4.2 adds explicit receiver pairing and paired-sender storage; until M2.4.3 authentication is implemented, WSS remains development-only and unauthenticated.
