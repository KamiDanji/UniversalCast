# M2.3 — Android TV mDNS / DNS-SD Discovery

## Scope

The Android TV receiver publishes the same DNS-SD service as the Windows receiver simulator:

- Service domain: `_universalcast._tcp.local.`
- Android `NsdManager` service type: `_universalcast._tcp.`
- Control port: `8765`
- WebSocket path: `/ucp`

The advertisement uses these TXT attributes:

| Key | Value |
|---|---|
| `ucp` | `1.0` |
| `id` | Stable random device UUID stored in app-private preferences |
| `name` | `UniversalCast Android TV` |
| `path` | `/ucp` |
| `tls` | `0` |
| `mode` | `development` |

TXT records are discovery hints, not authentication. No media URL, bearer token, pairing secret, or credential is broadcast. `tls=0` and `mode=development` explicitly describe the current unauthenticated development endpoint.

## Lifecycle and failure handling

- Discovery starts with the receiver Activity and is stopped when that Activity is destroyed.
- The Android NSD registration is refreshed after network availability/loss callbacks.
- Registration and unregistration errors are shown in the receiver UI; they do not stop Media3 or the UCP WebSocket server.
- Manual IP connection remains available if multicast discovery is blocked.
- This milestone does not provide background advertising while the Activity is stopped. A later production service lifecycle can move discovery into a foreground/service-owned receiver process.

## Validation

Run Android unit tests and build:

```powershell
.\gradlew :app:testDebugUnitTest
.\gradlew :app:assembleDebug
```

On a device/emulator connected to the same multicast-capable LAN, start the receiver. From the Windows PC on that same LAN, run this repository-root command:

```powershell
pnpm --filter @universalcast/receiver-simulator test:android-mdns
```

The browser waits up to 15 seconds for the Android receiver and validates its port, UCP version, path, development-mode hints, stable device ID, and resolved host/address. If needed, override the wait with `UCP_DISCOVERY_TIMEOUT_MS=30000` or the expected TXT display name with `UCP_ANDROID_DEVICE_NAME`.

After discovery passes, connect to `ws://<resolved-host>:8765/ucp` (the existing Android live UCP test can verify the control endpoint).

The Android emulator's multicast behavior can differ from a physical Android TV. A physical same-LAN test is the authoritative interoperability check.

## Security boundary

M2.3 does not change M2.2's security posture. The UCP endpoint remains plain `ws://`, unauthenticated, and intended only for a trusted development LAN. Do not port-forward it or expose it to untrusted networks. Discovery does not authenticate a receiver; authenticated pairing and TLS remain M2.4 work.
