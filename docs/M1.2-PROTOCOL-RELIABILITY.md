# M1.2 — Protocol reliability

This milestone hardens the development receiver's UCP message handling before session or media commands are introduced.

## Implemented behavior

- Validates JSON and the UCP request envelope before processing it.
- Requires a positive, safe-integer `seq` and an RFC 3339 timestamp with an explicit timezone.
- Requires `connection.hello` to be the first request on each WebSocket connection.
- Negotiates the mutually supported protocol version using `payload.supportedVersions` and returns `negotiatedVersion` in `connection.welcome`.
- Returns `UNSUPPORTED_VERSION` when the envelope version is unsupported or there is no common version.
- Enforces strictly increasing incoming sequence numbers per connection.
- Generates strictly increasing outgoing sequence numbers per connection, including error responses.
- Rejects duplicate request IDs within a bounded per-connection deduplication window.
- Returns structured `INVALID_MESSAGE` and `UNSUPPORTED_ACTION` errors, correlating errors with `replyTo` whenever a valid request ID is available.

The simulator still does not implement pairing, authentication, TLS, sessions, or media playback. It remains development-only and must not be exposed to untrusted networks.

## Run automated tests

From the repository root:

```powershell
pnpm install
pnpm --filter @universalcast/receiver-simulator test
pnpm --filter @universalcast/receiver-simulator typecheck
```

The tests cover a successful hello/welcome exchange, malformed JSON, invalid envelopes, unsupported versions, no common version, handshake ordering, unsupported actions, duplicate request IDs, incoming sequence ordering, and outgoing sequence ordering.

## Manual smoke test

Terminal 1:

```powershell
pnpm --filter @universalcast/receiver-simulator dev
```

Terminal 2:

```powershell
pnpm --filter @universalcast/protocol-debugger dev -- --host=192.168.2.15 --port=8765
```

Expected welcome details include:

```json
{
  "action": "connection.welcome",
  "seq": 1,
  "payload": {
    "negotiatedVersion": "1.0",
    "protocolVersions": ["1.0"]
  }
}
```

The exact message ID, timestamp, and device name will differ.
