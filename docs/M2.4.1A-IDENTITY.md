# M2.4.1a — Android Keystore receiver identity (provisioning only)

This patch adds `ReceiverIdentity`, an Android Keystore-backed EC P-256 signing identity. The private key is non-exportable through the Android Keystore API. It persists across ordinary app restarts and upgrades, but is normally removed when app data is deleted or the app is uninstalled.

**Security status:** This patch does NOT turn on TLS, does NOT authenticate senders, and does NOT secure the existing `ws://` UCP server. Keep port 8765 limited to a trusted development network. Do not advertise `tls=1` or `mode=secure` yet.

## Integrate and smoke test

1. Extract the patch at the UniversalCast repo root.
2. Build: `cd apps/android-receiver; .\gradlew.bat :app:testDebugUnitTest; .\gradlew.bat :app:assembleDebug`.
3. In `MainActivity.onCreate`, provision off the UI thread, e.g.:

```kotlin
Thread {
    runCatching { com.universalcast.receiver.security.ReceiverIdentity().loadOrCreate() }
        .onSuccess { identity -> android.util.Log.i("UniversalCastIdentity", "Identity ready: ${identity.certificateFingerprintSha256}") }
        .onFailure { error -> android.util.Log.e("UniversalCastIdentity", "Identity provisioning failed", error) }
}.start()
```

4. Reinstall with `adb install -r` (do not uninstall), launch twice and confirm the same fingerprint in `adb logcat -s UniversalCastIdentity:I '*:S'`.
5. **Never** log the private key, add a private-key export path, or treat a fingerprint alone as authentication.

## Before moving to M2.4.1b TLS

- Validate that the Android Keystore-generated X.509 certificate is usable for server TLS (key usages, validity, signature and KeyManager compatibility). An Android Keystore signing identity is not automatically a valid TLS server certificate.
- Use a separate, explicit TLS certificate lifecycle if needed. Pin the receiver's TLS certificate/public key during pairing, with out-of-band approval. Do not enable `wss://` advertisement until the TLS endpoint and pinning have been tested.
- Move the plaintext dev endpoint behind an explicit debug-only build flag, or disable it before enabling production security.
- Verify restart persistence, reinstall behavior, and failure recovery on an actual Android TV device.
